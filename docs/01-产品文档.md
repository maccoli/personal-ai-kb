# 01 · 产品文档（MVP 六格子）

> 方法论：MVP 是滑板车不是半辆车 -- 小可以、慢可以，但必须能完整完成一件事（输入 → 处理 → 输出闭环）。
> 用法：先照「模板」填你自己的六格子，填不出来或填完觉得「跟现有产品差不多」，就回去重新挖需求。

## 模板（照填）

| 格子 | 说明 | 内容（你来填写） |
| --- | --- | --- |
| 用户 | 这个产品服务谁（就一个人，就是你自己） | |
| 问题 | 解决我什么具体痛点（一句话，主痛点在前） | |
| 输入 | 我要喂什么进去 | |
| 处理 | AI 帮我做什么 | |
| 输出 | 我要拿到什么 | |
| 不做什么 | 明确写出不做哪些功能（最重要的格子，防止边做边加） | |
| MVP 闭环 | v1 跑通的最小流程（一句话） | |

## 填写示例（本仓库配套的实现）

| 格子 | 内容 |
| --- | --- |
| 用户 | 我自己 |
| 问题 | 主痛点：工作项目资料索引找不到，无法针对关键词快速回答；次痛点：项目总结难产，绩效总结和周报缺素材 |
| 输入 | 文档 / 网页链接（示例：内部文档平台链接），手动输入的话语 |
| 处理 | AI 读取链接的文档/图片内容 → 总结 → 打标签 → 更新索引 |
| 输出 | 根据关键词获取对应项目资料并快速回答；项目总结；工作总结 |
| 不做什么 | 不做简历生成（后续迭代）、不做 IM 对接、不做自动周报（v1 手动触发）、不做数据库、不做配图、不做协作、不做多端、不做音视频识别 |
| MVP 闭环 | 丢一个链接或一段话进知识库 → AI 读取、总结、打标签、更新索引 → 自然语言提问，按关键词快速获取项目资料和总结 |

## 填写提示

- **问题**：只写「反复扎你、不解决会持续难受」的痛点，别碰「想想就过」的痒点。
- **输入**：v1 锁死 1-2 个你最高频的来源，别写「各种链接」-- 不同来源的读取成本差异巨大。
- **不做什么**：从你自己的欲望清单里砍，别抄别人的；它是防止 MVP 烂尾的最重要一格。
