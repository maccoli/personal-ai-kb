# 02 · 架构文档（进 / 存 / 取 三问）

> 方法论：产品思维回答「我要做什么」，架构思维回答「东西怎么走」。普通人画架构只需回答三问：**进**（东西从哪来）、**存**（分几层、每层放什么）、**取**（怎么出去、给谁用）。
> 四条铁律：先画流再想功能 / 先画「取」再画「进」/ 只画「东西」不画「工具」/ 架构分版本，v1 能跑通就行。

配套架构图：`assets/架构图.png`（源文件 `assets/架构图.html`，改完用浏览器重新截图即可）。

## 一、取 -- 东西怎么出去、给谁用（先填这块，至少 2 条流）

| 输出流 | 谁来取 | 什么时候取 | 取什么形式 |
| --- | --- | --- | --- |
| 项目内容问答 | 我 | 随时 | AI 问答方式 |
| 项目总结 | 我 | 随时 | AI 问答方式 |
| 近期工作总结 | 我 | 随时 | AI 问答方式 |

> 「取」是最容易漏的一问 -- 只想清楚进和存，你做出来的只是精美的收藏夹，不是知识库。

## 二、存 -- 东西存哪、怎么组织

| 层 | 这层存什么 | 只读还是可读写 | 备注 |
| --- | --- | --- | --- |
| 原料层 | 链接抓取的原文 markdown（保留原始 URL，错了能回链核对）、手动输入的文字（统一存为 markdown），原样保存 | 只读 | 原料只读不改，错了能回退 |
| 加工层 | 两类笔记：① 单源笔记 -- 一条原料对应一篇（总结 + 标签）；② 项目页 -- 同一项目的多篇单源笔记综合成一页（多对一），直接支撑「项目总结」取流 | 可读写 | 项目页是「编译 > 检索」的落地 |
| 目录层 | 存「关键词 / 标签 / 项目 → 加工层笔记」的映射目录，本身不存知识内容，只做导航 | 可读写 | 每入库一条笔记就反向更新它；取的时候先查它定位笔记，再读笔记本体 |

## 三、进 -- 东西从哪来

| 输入源 | 触发方式 | 格式 |
| --- | --- | --- |
| 文档 / 网页链接 | 人工投入 | 链接 |
| 人工输入 | 人工投入 | 文字或富文本 |

## 四、自检

- [x] 「取」至少有 2 条流
- [x] 原料（原文）和成品（笔记）分层，原料只读、错了能回退
- [x] 每条「进」都能追到某条「取」，对不上的砍掉
- [x] 全文只有「东西」和「动作」，没有出现工具和技术名（那是技术文档的事）

## 数据流总述

链接 / 手动输入 → 原料层（原文 md，只读）→ 加工层（单源笔记 + 项目页）→ 目录层（索引，反向更新）→ 问答 / 项目总结 / 近期工作总结三条取流。
