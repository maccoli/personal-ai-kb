# 03 · 技术文档（选型与决策）

> 选型四原则：**AI 最熟**（AI 写得顺手、读得懂的格式和工具）/ **本地能跑**（不依赖外部服务）/ **文件优先**（文件系统优先于数据库）/ **社区大**（遇到问题好查）。

## 一、进 -- 技术栈

| 环节 | 推荐 | 为什么选它 | 更简单的替代 |
| --- | --- | --- | --- |
| 链接读取 | 当前环境可用的读取工具：内部文档平台配官方工具 / CLI / skill；公开网页用 AI 自带的 web fetch | 免自己处理登录态和反爬；AI 直接调用 | 手动复制全文粘贴（零依赖兜底，永远可用） |
| 手动输入 | 会话里直接贴文字，或丢一个 `.md` 进 `inbox/` | 零工具，AI 最熟的输入方式 | 无（已是最简） |

## 二、存 -- 技术栈

| 层 / 环节 | 推荐 | 为什么选它 | 更简单的替代 |
| --- | --- | --- | --- |
| 全部内容载体 | 本地文件夹 + Markdown 文件 | 文件优先、AI 最熟 md、天然可读可 diff | 无（这就是最简） |
| 原料层 `raw/` | 一个输入一个 md，文件名 `YYYY-MM-DD-标题.md`，文首记原始 URL 和入库时间 | 只读约定 + 回链可核对原文 | 无 |
| 加工层 `notes/` + `projects/` | 单源笔记一篇一个 md，用 YAML frontmatter 存 `type` / `project` / `tags` / `source` / `date`；项目页一个项目一个 md | frontmatter 是 AI 最熟的结构化方式，社区大（Obsidian/Jekyll 通用约定） | 正文首行写「标签：xx」（更随意，机器读略差） |
| 目录层 `index.md` | 单个 md 文件，按项目 / 标签分组的「关键词 → 笔记」映射清单 | 「编译 > 检索」的落地：AI 读一个文件就掌握全库导航 | 量大后再拆 `index/` 多文件（v1 不用） |
| 处理引擎 | 仓库根目录的 `AGENTS.md`（入库 / 问答流程提示词），AI 会话执行 | 零代码，流程即提示词；改流程就是改文档，不用调试 | Python/Node 脚本（v1 反而更重） |
| 版本保险 | 本地 Git，入库流程末尾 AI 自动 commit | 原料只读 + 笔记误改可回退 | 不做也行 -- 靠 raw 只读约定 + 系统备份 |

## 三、取 -- 技术栈

| 流 | 推荐 | 为什么选它 | 更简单的替代 |
| --- | --- | --- | --- |
| 三条流统一入口（问答 / 项目总结 / 近期工作总结） | 同一个 AI 会话，自然语言提问 | AI 先读 `index.md` 定位 → 读项目页 / 笔记 → 回答；零额外组件 | 无 |
| 检索兜底 | `rg`（ripgrep）全文搜 | 索引失灵时的备胎，命令 AI 熟 | `ls` + 人工翻（更慢） |
| 向量检索 / RAG | **不做** | 几十到几百篇的量级用不上；索引 + 项目页就是「编译 > 检索」；引入违背「能少就少」 | 单源笔记超过约 500 篇再评估 |

## 四、最简清单（能不用就不用、能少就少）

**要的，就 5 样**：

1. 一个文件夹（`kb/`，本地 Git 管理）
2. Markdown 文件 -- `raw/` `notes/` `projects/` `index.md` `inbox/`
3. 一份操作手册（`AGENTS.md`：入库流程 + 问答/总结流程）
4. 一个链接读取工具（按你的环境选，兜底是手动粘贴）
5. 一个 AI 编程助手（Kimi Code / Claude Code / Codex 等）

**明确不装的**：数据库、爬虫框架、向量库、UI/前端、定时任务、云同步服务、Obsidian 等笔记软件。

## 五、决策记录（推荐默认，可按需改）

| # | 问题 | 决策 |
| --- | --- | --- |
| 1 | 知识库根目录 | 仓库内 `kb/` 子目录 |
| 2 | 入库触发指令 | 固化为「知识库入库：<链接> 或文字」，写进 `AGENTS.md` |
| 3 | 标签体系 | AI 打标签并维护 `tags.md`：先匹配已有，没有才新增录入；**每次打标签前先和用户确认**（嫌烦可降级为「自动打、定期批量审」） |
| 4 | 项目页更新时机 | 每入库一篇就重写所属项目的项目页（只重写这一个）；不属于任何现有项目时提出新建并确认 |
| 5 | 图片处理深度 | 多模态读图总结（读取工具下载图片，模型读图） |
| 6 | 本地 Git | 要；入库流程末尾 AI 自动 commit（仅 `kb/`） |
| 7 | 文件命名规则 | `YYYY-MM-DD-标题.md`，标题由 AI 起 |
